# Cough AI — ระบบคัดกรองโรคด้วยเสียงไอแบบไม่รุกล้ำ

เว็บแอปที่ให้ผู้ใช้บันทึกหรืออัปโหลดเสียงไอประมาณ 5 วินาที แล้ว AI ประเมินความน่าจะเป็นของ 3 กลุ่ม — **Healthy / COVID-19 / Symptomatic** — พร้อมระดับความเสี่ยง ผ่านเบราว์เซอร์บนสมาร์ตโฟนได้ทันที ไม่ต้องติดตั้งแอปหรือใช้อุปกรณ์เพิ่มเติม ผลออกภายในไม่กี่วินาที

> ⚠️ เป็นเครื่องมือ **คัดกรองเบื้องต้น** ไม่ใช่การวินิจฉัยทางการแพทย์ (แพทย์ที่ปรึกษาโครงการแนะนำว่าเสียงไอไวต่อเพศ อายุ และปัจจัยอื่นมาก) ผลต้องได้รับการตรวจยืนยันโดยบุคลากรทางการแพทย์

## ทำไมต้องมี Cough AI

ตามรายงานขององค์การอนามัยโลกและธนาคารโลก ประชากรราว 4.6 พันล้านคนทั่วโลกยังเข้าไม่ถึงบริการสุขภาพพื้นฐานที่จำเป็น ระยะทาง เวลา และค่าใช้จ่ายทำให้ผู้ที่ไอและมีความเสี่ยงต่อโรคทางเดินหายใจเข้าถึงการประเมินเบื้องต้นได้ล่าช้า และยังไม่มีเครื่องมือที่ประชาชนใช้วิเคราะห์อาการไอเองที่บ้านได้ง่าย Cough AI ทำให้การคัดกรองเบื้องต้นทำได้จากสมาร์ตโฟนเครื่องเดียว โดยไม่ต้องเจาะเลือดหรือใช้อุปกรณ์สอดเข้าร่างกาย

## วิธีใช้ (3 ขั้นตอน)

1. **Cough** — อัดเสียงไอประมาณ 5 วินาที หรืออัปโหลดไฟล์เสียง
2. **Process** — ระบบตัดส่วนเงียบ ปรับระดับเสียง แล้วสกัดคุณลักษณะ
3. **Classification** — แสดงความน่าจะเป็นของ 3 กลุ่ม และระดับความเสี่ยง

## ระบบทำงานอย่างไร

```
เสียงไอ → ทำความสะอาด / normalize / ตัดส่วนเงียบ
        ├─ Random Forest : 416 ฟีเจอร์เสียง (MFCC, Delta MFCC, Mel, Spectral Centroid,
        │                   Zero-Crossing Rate, Roll-off, Chromagram, ...)
        └─ CNN           : Mel-Spectrogram 128×128
        → Ensemble แบบ Soft-Voting (CNN 50% + RF 50%)
        → ความน่าจะเป็น Healthy / COVID-19 / Symptomatic + ระดับความเสี่ยง
```

- **Backend:** Flask + Gunicorn · **Frontend:** HTML / CSS / JavaScript · **โมเดล:** TensorFlow (CNN), scikit-learn (RF), librosa
- **Deploy:** Vercel — ไฟล์โมเดลไม่อยู่ใน repo แอปดาวน์โหลดจาก Google Drive ตอนเริ่มทำงาน

## ข้อมูลที่ใช้

ชุดข้อมูลเสียงไอสาธารณะ **COUGHVID** (label จากสถานะที่ผู้อัดรายงาน) หลังทำความสะอาดและตัดส่วนเงียบ ได้ **20,188 ไฟล์**

| Healthy | Symptomatic | COVID-19 |
|---|---|---|
| 15,091 | 3,807 | 1,290 |

คลาสไม่สมดุล จึงปรับสมดุลด้วย SMOTE (RF) และ oversampling (CNN) ก่อนแบ่งชุดฝึก/ชุดทดสอบแบบ 80/20 — ชุดฝึก 36,218 ไฟล์ ชุดทดสอบ 9,055 ไฟล์ (คลาสละ ≈ 3,018)

## ผลการทดสอบ

| โมเดล | Accuracy | Macro-Precision | Macro-Recall | Macro-F1 | Macro-AUC |
|---|---|---|---|---|---|
| Random Forest | 90.89% | 90.86% | 90.89% | 90.86% | 0.98 |
| CNN | 90.84% | 90.93% | 90.84% | 90.72% | 0.98 |
| **CNN + RF (Ensemble ที่ใช้ในระบบ)** | **93.20%** | **93.27%** | **93.20%** | **93.13%** | **0.99** |

Ensemble — sensitivity / specificity ต่อคลาส: COVID-19 1.00 / 0.99 · Healthy 0.85 / 0.97 · Symptomatic 0.94 / 0.94

**วิธีอ่านตัวเลขนี้:** ชุดทดสอบถูกสร้างหลังปรับสมดุลคลาส (oversample ก่อนแบ่ง) ไฟล์ของคลาสที่มีน้อย โดยเฉพาะ COVID-19 ที่มีเพียง 1,290 ไฟล์ จึงถูกทำซ้ำ/สังเคราะห์ และบางส่วนปรากฏทั้งในชุดฝึกและชุดทดสอบ ตัวเลขข้างต้นจึง **เหมาะกับการเปรียบเทียบโมเดลกันเอง และสูงกว่าที่คาดจากเสียงไอใหม่ในการใช้งานจริง** แถว Healthy (คลาสที่ไม่ถูกทำซ้ำ) 0.85 สะท้อนระดับที่สมจริงกว่า การประเมินแบบแยกชุดทดสอบก่อนปรับสมดุล (`pipeline/*_clean_new.py` วิธีรันใน [`pipeline/EVALUATION.md`](pipeline/EVALUATION.md)) จะเพิ่มผลในหัวข้อนี้เมื่อประเมินเสร็จ

## ข้อจำกัด

- label เป็นสถานะที่ผู้อัดรายงานเอง (self-reported) ไม่ได้ยืนยันด้วยผลตรวจทางการแพทย์
- การแบ่งข้อมูลทำตามไฟล์ ไม่ใช่ตามผู้พูด (ข้อมูลสาธารณะไม่มีรหัสผู้พูด) คนเดียวกันที่อัดหลายไฟล์อาจอยู่ทั้งสองฝั่ง
- COVID-19 มีน้อยมาก (1,290 ไฟล์) ต้องพึ่ง oversampling
- ยังไม่ได้ทดสอบกับเสียงที่อัดจากอุปกรณ์/สภาพแวดล้อมจริงนอกชุดข้อมูล (ไมโครโฟนมือถือ เสียงรบกวน)
- เป็นเครื่องมือคัดกรอง ไม่ควรใช้ตัดสินใจทางการรักษา

## รัน local

ไฟล์โมเดล (`cough_rf_model.pkl`, `cough_cnn_model.h5`) **ไม่อยู่ใน repo** แอปดาวน์โหลดจาก Google Drive ตั้ง environment variable `RF_MODEL_FILE_ID` และ `CNN_MODEL_FILE_ID`

```bash
pip install -r requirements.txt
python app.py
```
